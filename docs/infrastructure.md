# インフラ構成：TaskManagement

本アプリは、学習目的でAWS上にデプロイできる環境を用意している。無料利用枠に収まる最小構成とし、
インフラはTerraform（IaC）でコード管理する。個人利用・認証機能なしを前提とした構成であり、
本番運用水準のセキュリティ・可用性は求めていない（詳細は[要件定義書の非機能要件](requirements.md#非機能要件)を参照）。

## 構成図

```
                              Internet
                                  │
                 （自分のIPアドレスのみ許可: 22 / 80 / 8080）
                                  │
        ┌─────────────────────────────────────────────┐
        │  VPC                                          │
        │                                                │
        │  ┌───────────────────────────────────────┐   │
        │  │ パブリックサブネット（AZ-a）              │   │
        │  │  ┌─────────────────────────────────┐  │   │
        │  │  │ EC2                               │  │   │
        │  │  │  Docker Compose                   │  │   │
        │  │  │   ├─ frontend（nginx, :80）        │  │   │
        │  │  │   └─ backend（Spring Boot, :8080）  │  │   │
        │  │  └─────────────────────────────────┘  │   │
        │  └───────────────────────────────────────┘   │
        │                     │                          │
        │                     │ :5432（EC2からのみ許可）  │
        │                     ▼                          │
        │  ┌───────────────────────────────────────┐   │
```

インターネットゲートウェイを使い、NAT Gatewayは使用しない（コスト削減のため、EC2をパブリックサブネットに直接配置する構成）。

## 使用しているAWSサービス

| サービス | 役割 |
|---|---|
| VPC / サブネット / インターネットゲートウェイ / ルートテーブル | 新規作成した専用ネットワーク。パブリックサブネットを2つ作成（RDSのサブネットグループが複数AZを必須とするため） |
| EC2 | アプリケーション本体（フロントエンド・バックエンド）をDocker Composeで起動するサーバー。無料利用枠対象のインスタンスタイプを使用 |
| RDS（PostgreSQL） | データベース。無料利用枠対象のインスタンスクラス・シングルAZ構成。EC2以外からはアクセス不可 |
| セキュリティグループ（EC2用） | SSH・フロントエンド（HTTP）・バックエンドAPIとも、自分のグローバルIPアドレスのみ許可 |
| セキュリティグループ（RDS用） | EC2用セキュリティグループからのPostgreSQL通信のみ許可 |

ALB・NAT Gateway・ECRなど、恒常的な課金が発生しやすいサービスは使用していない。

## セキュリティ方針

- RDSは「`publicly_accessible=false`（そもそも公開IPを持たない）」と「セキュリティグループでEC2以外からの接続を拒否」の二重の制限で保護している
- EC2へのSSH・HTTP・バックエンドAPIへのアクセスは、自分のグローバルIPアドレスのみに制限している（不特定多数への公開はしない）
- アクセス元IPが変わった場合は、インフラ側の設定変更が必要になる

## コンテナ構成

| ファイル | 役割 |
|---|---|
| `Dockerfile`（リポジトリ直下） | バックエンド（Spring Boot）のマルチステージビルド。ビルド用イメージでJARを作成し、実行用の軽量なイメージにコピーする |
| `frontend/Dockerfile` | フロントエンド（React）をViteでビルドし、静的ファイルをnginxで配信するイメージを作成する |
| `docker-compose.prod.yml` | EC2上でbackend・frontendコンテナを起動する。backendはRDSに接続し、DBコンテナは含まない（ローカル開発用の`docker-compose.yml`とは別ファイル） |

## デプロイの仕組み（概要）

EC2起動時に、`infra/user_data.sh.tpl`をもとにしたブートストラップスクリプトが自動実行され、以下を行う。

1. Docker・Docker Composeのインストール
2. 本リポジトリ（GitHub）のclone
3. `docker-compose.prod.yml`によるビルド・起動

この一連の流れはTerraformの`apply`実行だけで完結し、手動でのサーバー操作を必要としない。

## Terraformのディレクトリ構成（`infra/`）

インフラの実際の定義は`infra/`ディレクトリのTerraformコード（`.tf`ファイル）を参照。役割ごとにファイルを分けている。

| ファイル | 内容 |
|---|---|
| `versions.tf` | Terraform・AWSプロバイダーのバージョン指定 |
| `variables.tf` | リージョン・インスタンスタイプ・SSH許可IPなどの変数定義 |
| `network.tf` | VPC・パブリックサブネット・インターネットゲートウェイ・ルートテーブル |
| `security_groups.tf` | EC2用・RDS用のセキュリティグループ |
| `ec2.tf` | AMI検索・SSHキーペア登録・EC2インスタンス |
| `rds.tf` | RDS（PostgreSQL）とDBサブネットグループ |
| `user_data.sh.tpl` | EC2起動時に実行されるブートストラップスクリプトのテンプレート |
| `outputs.tf` | 適用後に表示される情報（パブリックIP・アクセスURL・SSHコマンドなど） |
| `terraform.tfvars.example` | 環境固有の値（SSH許可IP・DBパスワードなど）のひな形。実際の値を書いた`terraform.tfvars`はGit管理対象外 |

具体的な設定値（インスタンスタイプ・ストレージ容量・CIDRなど）は変更される可能性があるため、このドキュメントには記載せず、上記の`.tf`ファイルを直接参照すること。

## 無料利用枠に関する方針

- EC2・RDSともに、AWSアカウント作成から12ヶ月間無料の利用枠に対応したインスタンスタイプ・構成を選んでいる
- 想定外の課金に気づけるよう、AWSの予算アラート（Budgets）を設定しておくことを推奨する
- 使わない期間は`terraform destroy`でリソースを削除し、課金を止める運用とする
